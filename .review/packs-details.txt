---COMMENT #1 [security/high] lines 25-25---
CONTENT:
`set:html` combined with `JSON.stringify(ssrData)` is vulnerable to script-tag breakout. `JSON.stringify` does not escape the `</script>` sequence. If any string value inside `serverConfig` (e.g., the `tools` JSONField, or a crafted `widgetPath`/`cdnPath` URL) contains `</script>`, the browser will close this script tag prematurely and interpret subsequent content as raw HTML — enabling stored XSS. While only admins currently see the `serverConfig` payload, the page is publicly accessible and the injection occurs in the HTML before the client-side admin check runs.

Recommendation: escape `</` sequences before injection, for example:
```astro
<script type="application/json" id="l2d-ssr-data" set:html={JSON.stringify(ssrData).replace(/<\//g, '<\\/')} />
```
Or use a different data-passing strategy such as a `define:vars`-based inline script, or base64-encoding the payload.
---SUGGESTION_CODE---
  <script type="application/json" id="l2d-ssr-data" set:html={JSON.stringify(ssrData).replace(/<\//g, '<\\/')} />
---EXISTING_CODE---
