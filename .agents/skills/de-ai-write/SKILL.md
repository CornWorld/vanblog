# 去 AI 味 (de-ai-write)

> 目标读者：vanblog 及任何项目的文档作者 / 审查者。写新文档、或把 AI 生成的草稿改成人话时用。

## 一、什么是「AI 味」

AI 生成的文本有几个可辨认的机械特征。它们不是语法错误，而是「读起来像机器写的」的语感问题。逐条检测，命中即修。

## 二、特征清单（检测到即修）

1. **空洞连接 / 总结词**：`总之` `综上所述` `值得注意的是` `需要注意的是` `换句话说` `我们可以看到` `显而易见` `毫无疑问` `值得一提的是` `在此基础上`
2. **客套开场 / 结尾**：`本文将介绍` `希望对你有所帮助` `欢迎 star` `感谢阅读` `以上就是` `让我们一起来` `接下来我们谈谈`
3. **排比堆砌**：列表项全部同句式、同长度，为对称而对称（如「支持 X、支持 Y、支持 Z」连排）
4. **假精确 / 夸张副词**：`近乎完美` `无缝衔接` `极大提升` `极致` `非常` `十分` `相当` `特别` `非常稳定` `高效可靠`
5. **注水填充句**：不携带信息的过渡，如 `接下来，我们来聊聊…` `这无疑是一个很好的选择`
6. **机械转折**：`然而` `与此同时` `此外` `另一方面` 在一段里密集出现
7. **营销腔**：形容词堆叠、感叹号连用、`让你的…` 句式
8. **emoji 滥用**：正文里塞一堆 🎉✨🚀💡 装点
9. **节奏单一**：所有句子等长，无长短交错
10. **把简单事说复杂**：一个词能说清的非要用一句，或名词化堆叠（`…的解决方案` `…的能力` `…的机制`）

## 三、重写原则

- **直说**：先结论，再细节；能一句话说清的不写三段。
- **信息密度优先**：删掉每个不携带信息的词。删完后语义不变，就删对了。
- **具体代替抽象**：写真实端口 / 命令 / 路径 / 截图，不写「高效稳定体验好」。
- **短句为主，长短交错**：长句拆开，偶尔一句短的。
- **口语但准确**：像资深用户写给新用户，不端着，但也不丢准确度。
- **少用「我们」**：能用祈使句就祈使句（`先备份` 而不是 `我们需要先进行备份`）。
- **列表动词开头**：每项用动词 / 名词短语直接说，避免全部「支持…支持…」。

## 四、流程

1. **读**目标文档（或接受一段草稿）。
2. **扫**：用第二节清单逐条扫描，记录命中项（`文件:行` + 原文）。
3. **改**：每处保留语义，砍注水，换掉 AI 腔，短句直说。
4. **复核**：对照清单确认无残留；保留文档的事实 / 链接 / 结构。
5. **输出**：改动摘要（改了什么、为什么），而非整篇重贴。

## 五、禁改（边界）

- **不改事实**：命令、端口、路径、环境变量、链接、默认值——这些是 `docs/quality/doc-standard.md` 的 SSOT 范围，只能引用不能改。
- **不删必要信息**：只删注水，不删步骤、警告、安全提示。
- **不牺牲清晰度**：「像人话」不等于含糊。让读者更快看懂，而不是更少信息。
- **不强行口语化**：正式文档（LICENSE、SECURITY）保持正式；本文只针对啰嗦的 AI 腔。

## 六、快速自查（写完后过一遍）

- [ ] 删掉「总之/综上所述/值得注意的是/我们需要」这类词后，句子还成立吗？成立→删。
- [ ] 有没有不承载信息的句子？有→删。
- [ ] 列表项是不是为了对称而对称？是→改写。
- [ ] 全文有没有一个「非常/十分/极致」？有→换成具体数字或删掉。
- [ ] 每个命令 / 端口 / 路径都精确、可照抄？是→通过。
